## Build verification

- Configuration: Release, MSVC 19.43.34808, CommonLibSSE-NG v11.0.0 commit `94faaed0c60eddd8347767f2d4d29a97c93bde8c`, `SKSE_SUPPORT_XBYAK=ON`
- Output: `build/release-msvc/AssetDoctor.dll` (1,896,448 bytes)
- SHA-256: `8BD891BBEB49D5F1A346828C4FC36A8EA6A112E2E8543DEC5CF23733DA7D91B7`
- Exports: `SKSEPlugin_Load`, `SKSEPlugin_Query`, `SKSEPlugin_Version`
- Static `SKSEPlugin_Version` values: plugin `1.1.1.0`, structure compatibility `0x3` (Address Library v5 plus CommonLib cross-runtime structure handling), runtime compatibility `0x1` (Address Library), minimum SKSE `0`
- Automated tests: the project defines no CTest tests

The rebuilt DLL's executable and data sections are byte-identical to the smoke-tested DLL (`85DEA5B2990579D422CE5334B3C6855EFC6BCCA23CA10D0D599E2DF90FB4CF99`). The files differ only in the two low bytes of the COFF timestamp, repeated in linker metadata.

The first in-game load reached CommonLib's trampoline allocator but failed after consuming a 14-byte pool for the first of two inline call hooks. The corrected build allocates the complete 28-byte pool once during `SKSE::Init`.

## Runtime smoke test

A fresh launch with Skyrim 1.7.104 and SKSE 2.3.1 loaded the corrected DLL (`85DEA5B2990579D422CE5334B3C6855EFC6BCCA23CA10D0D599E2DF90FB4CF99`) in the `1.7.104 experiment` MO2 profile. `AssetDoctor.log` records both 14-byte trampoline allocations, all three vtable hook installations, and successful ImGui initialization. The game proceeded past plugin initialization without the earlier trampoline allocation failure.

## Evidence boundary

The static checks prove that the checked Address Library database is format 5, contains the IDs used by Asset Doctor, and maps the configured hook sites to plausible instructions/code pointers in the checked executable. The smoke test proves that this DLL loads and completes hook and ImGui initialization in the tested profile. It does not establish long-session stability, save/load behavior, or exhaustive UI and asset-validation behavior.
